## 1. 上下文 (Context)

### 1.1 为何修订

ADR-0001 于 2026-09-15 交付后，经项目所有者的 16 条审查逐字核验，发现以下事实性错误与纪律未执行：

1. **钢铁定义漂移**：ADR-0001 §2.3 将钢铁定义为"硅基物理 / 平台机制的不可变边界"，而 constraints.md §2.0 现行定义为"硅基物理边界（渲染管线、显示面板、能耗定律）"。两份文档对"什么是钢铁"说法不一致，且 §2.0 未同步。该扩展自身亦未被一致执行——N-005（导航栈 LIFO）是最典型的平台机制，却被标为 [ENG] 陶土。
2. **钻石门槛未执行**：ADR-0001 §2.3 自定钻石门槛为"碳基生理 / 认知的不可变边界……且有充分学术共识支撑"。N-020~N-023 仅以 WCAG 条款为依据（合规契约，非学术共识），却全部标为钻石（可访问性刚需）。本次交付违反了本次 ADR 自己写的判定纪律。
3. **锚定表失实**：ADR-0001 §2.1 九行锚定表中仅 3 行与实际相符（N-006←P-021、N-013←P-014+C-003、N-016←P-011+公理二）；其余 6 行部分或全部落空——过半 N 约束是从文献直接引进的新认知原语（信息觅食、寻路理论、外部记忆），而非"由已有约束推出"，却未标记为"新增原语"。
4. **行数估计失实**：ADR-0001 §3.2 称 constraints.md"当前 145 行，有充足空间"；实际交付前已约 210 行、交付后 359 行，距 400 行解耦阈值仅 41 行。
5. **其他**：§2.2 要求每条约束附 [PHYS]/[ENG]/[GENE]/[PURPOSE]，与 system-summary"卷二不包含任何项目特定值"冲突（[GENE]/[PURPOSE] 在卷二非法）；§3.1 承诺的 derivation.md 激活流程纳入 N-系列、十一审引用、verify 校验均未落地，N-系列当前是"孤儿约束"（卷二有、卷三不激活、verify 不查、archive 未用）。

### 1.2 版本纪律

system-summary §防撕裂机制 4：每部文档冻结后不再原地修改，修正通过新版本实现，旧版本保留为历史。v10.1.0 已提交 git（冻结）。本批修订包含约束语义变更（N-002 硬度、N-020~23 拆分、来源类型列、§2.6 平台行为快照），按 semver 属 minor，版本号 **v10.1.0 → v10.2.0**（16 条审查清单中的"v10.1.1"标签作废）。v10.1.0 予以保留为历史，不作废。

### 1.3 方法论要求

phyt-DNA ADR 规则："Status: two states (Draft / Active); once Active cannot be overwritten, only Superseded。"ADR-0001 已 Active，因此本修订不原地修改 ADR-0001，而是以 ADR-0002 取代之；ADR-0001 状态迁移为 Superseded（规则允许的状态迁移，非内容覆盖），全文保留为历史。

## 2. 决策 (Decision)

### 2.1 决策内容

延续 ADR-0001 的核心决策：约束库新增 §2.4 导航与流转约束（N-001~N-023）。同时执行以下修订：

**1. 钢铁定义回撤。** 撤销 ADR-0001 §2.3 对钢铁的扩展，回归 constraints.md §2.0 现行定义：钢铁 = 硅基物理边界（渲染管线、显示面板、能耗定律）。平台机制不属于钢铁——它们随时间与厂商决策变化（如 UITabBarController ≥6 → More 是 iOS 版本行为，年度级变动）。平台机制的归属待 ADR-0000（phyt-DNA × Lumtract 管辖边界）确立后另行裁决，本修订不预判其结论。过渡期内，平台行为由 constraints.md 新增 §2.6 平台行为快照（带版本锚点、年度复审）承载，N-008 等约束的"硅基硬行为"表述同步改为引用该快照。

**2. 钻石门槛执行。** 按 ADR-0001 §2.3 自定门槛复核 N-020~N-023：

- 拆双标注：`[PHYS] 钻石（生理基础：运动障碍 / 低视力等碳基边界）+ [ENG]（WCAG x.y.z 条款实现）`——生理基础是钻石，WCAG 条款是合规契约（[ENG] 实现层）。
- AAA 级引用降级：N-003/N-006 引用的 WCAG 2.4.8 Location (AAA)、N-018 引用的 2.4.9 Link Purpose (AAA) 属最高级合规，非普遍义务，降级为参考级，不作为硬边界依据。
- 同批复核新发现（超出 16 条清单，但属同一纪律）：N-010 钻石（上下文切换成本）与 N-014 钻石（出口焦虑）当前依据仅为行业来源（Apple HIG / NN-g），按同一门槛需补学术锚定（C-001 预测加工 / C-003 情绪时间）或降级 [ENG]——v10.2.0 落地时一并执行。

**3. 锚定表修正。** 九行锚定关系按实际核验重写（见 §2.2），并新增"来源类型"列：`[派生自 P-xxx] / [新原语: 文献] / [平台行为: 版本] / [ENG]`。该列同时是校验器的输入：标"派生自"却查不到既有约束 ID 的，即冒充。

**4. N-002 摘除 P-020。** 可见导航项走识别（P-021），不直接映射工作记忆容量（P-020）；≤5 为 [ENG] 工程约定。4–8 项为文献实验值（Paap & Roske-Hofstrand 1986），非"充分学术共识"的钻石边界，一并标 [ENG]，边界声明保留出处。

**5. undo 5s 补源或标 [ENG]。** N-015 的"建议 undo 入口至少持续 5s"无来源，标 [ENG]（工程保守约定，参考 iOS 系统级撤销横幅的显示时长），不冒充生理阈值。

**6. 版本号与复审。** 约束库 v10.1.0 → v10.2.0；依 system-summary 版本绑定规则（约束库升级 → 依赖实例档案复审），正式触发 archive.md 复审（行动 #5）。

### 2.3 硬度判定纪律（保留并收紧）

- **钻石**：仅当约束陈述的是碳基生理 / 认知的不可变边界（如工作记忆容量、识别-回忆不对称），且有充分学术共识支撑。行业实证（NN/g 等）不构成学术共识。
- **钢铁**：仅当约束陈述的是硅基物理的不可变边界（渲染管线、显示面板、能耗定律）。平台机制不属钢铁，走 §2.6 平台行为快照（带版本锚点）。
- **陶土**：工程约定、行业惯例、项目基因。必须明确标注 `[ENG]` 并说明理由。**禁止将行业惯例包装成生理必然。**
- 任何量化阈值：若来自学术文献 / 官方指南，标注出处；若为工程保守约定，标注 `[ENG]` 并说明推导逻辑。
- **工具纪律（新增）**：校验器不得把 [ENG] 阈值写成硬断言——机器把陶土固化成钻石，比手写冒充更隐蔽。

### 2.4 不做什么 (Non-Goals)

- 不修改 philosophy.md（公理不可变）。
- 不修改 R/D/P/C/L 既有约束陈述（除本修订明确列出的 N-002 硬度、N-020~23 标注、N-010/N-014 依据补强）。
- 不改变 ADR-0001 的核心决策（新增 N-系列）。
- 不预判平台机制的最终管辖结论（留待 ADR-0000）。
- 本轮不拆分 constraints.md §2.4 为独立文件（解耦已列为 follow-up，见 §5 #6）。

## 3. 后果 (Consequences)

### 3.1 正面后果

1. **诚实性恢复**：锚定表真实、钻石门槛被执行、钢铁定义与 §2.0 一致。
2. **N-系列可被消费**：来源类型列成为校验器输入，"孤儿约束"开始有守门人。
3. **版本纪律示范**：v10.1.0 保留为历史，修正通过 v10.2.0 实现。
4. **ADR 纪律示范**：已接受 ADR 不可原地覆盖，修订以 ADR-0002 取代并保留 v1 全文。

### 3.2 负面后果与成本

1. **constraints.md 体积**：v10.2.0 预计约 385 行，逼近 400 行解耦阈值——拆分 §2.4 为独立文档已列为 follow-up（§5 #6），并在新增内容前强制执行。
2. **N-002 硬度降低**：≤5 不再具有"生理必然"外观，需设计团队理解 [ENG] 语义（经 navigation.md 索引硬度归属列缓解）。
3. **实例档案复审**：archive.md 现有案例需按 v10.2.0 复核（§5 #5）。
4. **认知负担**：双标注（钻石 + [ENG]）与来源类型列增加阅读成本——由 navigation.md 索引列与校验器输出缓解。
