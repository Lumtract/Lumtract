# ADR-0007：平台固化推翻路径的边界（功能失败型固化不可由推导推翻）

| 字段 | 值 |
| --- | --- |
| **状态** | 已接受 (Accepted) |
| **日期** | 2026-09-15 |
| **决策者** | 人类（项目所有者） |
| **方法论版本** | phyt-DNA v1.0 |
| **体系版本锚点** | 推导引擎 v10.3.0 → v10.4.0（§3.2.2 固化边界推翻段并入分类判定） |
| **相关** | ADR-0005（推翻路径五要素；本 ADR 为其补**边界分类**，不修改五要素）、ADR-0004 §2.1 #3（平台固化机制） |

> 本 ADR 只做一件事：给 ADR-0005 的推翻路径划定适用边界——**功能失败型平台固化不可由推导推翻**。这是实例推导前置修订（目标：电商下单，支付流程将撞上平台强制固化）。

---

## 1. 上下文 (Context)

ADR-0005 立"目的可推翻项目级硬边界（服从公理四）"，但未区分固化类型。实例推导目标（电商下单主流程）将撞上平台**强制**固化：

| 固化项 | 类型 | 不遵守的后果 |
| --- | --- | --- |
| iOS IAP（虚拟商品支付通道强制） | 平台规则 | 交易不可行 / App Store 审核失败 |
| 小程序支付通道（微信支付） | 平台规则 | 交易不可行 |
| Android 支付规则 | 平台规则 | 交易不可行 |
| 小程序页面栈上限（§2.6 已登记） | 平台事实 | navigateTo 直接失败，功能没了 |
| 预测性返回（OnBackInvokedCallback，API 33+） | 平台机制 | 返回行为与系统冲突 |

这类固化"不遵守就功能失败"，**不是体验权衡**。若推翻路径不加边界，首次应用就会得出荒谬结论（如"为了支付体验推翻 IAP 强制"）。

---

## 2. 决策 (Decision)

1. **固化分两类**：
   - **功能失败型**（平台规则 / 物理事实 / 平台机制强制）：不遵守 → 功能不可用、交易不可行、调用失败。**不可由推导推翻**。
   - **体验型**（项目内可裁决的体验权衡）：可被目的推翻（走 ADR-0005 五要素：目的三问 → 人类所有者裁决 → `[ENG: 调整为X，原因: Y，迁移成本: Z]` → 十一审复查）。
2. **功能失败型的裁决权在平台**：产品只能在"适配该平台固化"与"放弃该平台路径（换平台 / 砍功能）"之间决策。推导引擎与人类所有者都不得做出"违反固化"的裁决——这不是推导裁决范围，是产品-平台战略决策。
3. **判定方法（可机器化）**：固化项是否满足"不遵守 → 功能失败 / 不可用 / 交易不可行"？是 → 平台裁决通道；否 → 体验型，可走推翻路径。

**不做什么 (Non-Goals)**：不修改 ADR-0005 五要素；不修改 ADR-0004 固化机制；不预判具体平台策略（适配或放弃由产品决策）。

---

## 3. 后果 (Consequences)

1. 推翻路径首次应用（电商支付流程）不会误入"推翻 IAP"的荒谬分支——固化冲突直接走平台裁决通道。
2. 判定方法可进推导引擎（§3.2.2 同步），冲突裁决时可自动分类。
3. 风险：功能失败型判定边界模糊（如平台规则随版本变化）——由 §2.6 年度复审兜底，判定以快照版本锚点为准。
