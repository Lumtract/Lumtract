## 1. 上下文 (Context)

Lumtract 体系内存在三套治理逻辑，此前无明确边界：

- **phyt-DNA（元-方法论）**：管"体系文档如何演进"（VISION → DNA → RNA → SPEC → PLAN → GROWTH → DEPRECATE → archive）。
- **水之波光（领域-方法论）**：管"任何界面的设计值如何推导"（公理 → 约束库 → 推导引擎 → 实例档案）。
- **Lumtract 软件（对象层）**：被上两层共同约束的产物。

边界缺失已造成实际越界：ADR-0001 §2.3 把"平台机制"塞进钢铁定义（把随时间变化的平台行为当成物理真理），正是"文档层越权定义设计值层概念"的案例。项目所有者提出三层分层（"这个分层我觉得成立"），本 ADR 将其契约化。

---

## 2. 决策 (Decision)

### 2.1 三层模型

| 层 | 主体 | 管什么 | 产出 | 落地文档 |
| --- | --- | --- | --- | --- |
| 元-方法论 | phyt-DNA | 体系文档如何演进 | 版本决策、ADR、[GENE] 定义 | 本项目 ADR（docs/adrs/）；方法论文档位于外部 |
| 领域-方法论 | 水之波光 | 任何界面的设计值如何推导（含 Lumtract 自己的 UI） | 设计值 + 来源标注 + 负债标记 | philosophy / constraints / derivation / archive / system-summary / navigation |
| 对象层 | Lumtract 软件 | 被约束的产物 | 可运行的软件 | web-viewer/src、scripts |

### 2.2 两个接口契约

1. **DNA → [GENE]**：phyt-DNA 的 DNA 层定义"这个项目是什么"，正是水之波光的 [GENE] 输入。语义映射：DNA 决定项目身份 → [GENE] 是水之波光中可被引用的项目基因（视觉皮肤、品牌特征），非公理。
2. **archive → SPEC**：水之波光的 archive.md 记录完整推导链，正是 phyt-DNA 的 SPEC 输入。**推导记录即规格**：实例档案既是水之波光的产出，又是 phyt-DNA 生长决策的事实依据。

### 2.3 三条硬边界

1. **phyt-DNA 的 SPEC 不得含视觉值**：SPEC 说"要做什么功能"，不得说"这个按钮 12px 圆角"。色值 / 尺寸 / 形状等设计值只能由水之波光链路（约束库 → 推导引擎 → 实例档案）产出。违反即侵入领地，两套方法论当场打架。
2. **钻石约束对 phyt-DNA 同样生效**：工程便利不能豁免生存权。PLAN 可以说"这期不做主题切换"（记入负债），不能说"为赶工把对比度降到 3:1"。
3. **archive 与"彻底移除"的仲裁**：archive = 冷存储（保留，供审计追溯）；"彻底移除" = 活跃集（不参与当前推导）。统一规则：进 archive 的内容必须标 `[OBSOLETE: 被X替代]`，且不参与任何约束激活。两者同时满足：phyt-DNA 的可追溯性 + 水之波光的反幽灵机制。

### 2.4 平台机制归属（补充裁决）

ADR-0002 已回撤"平台机制进钢铁"。本 ADR 正式裁决：**平台机制**（导航栈 LIFO、UITabBarController ≥6 → More、UISheetPresentationController detents、State Restoration opt-in 等）属**可随时间变化的行为事实**，归 constraints.md §2.6 平台行为快照（带版本锚点、年度复审），不属钢铁（物理不可变），也不属钻石（生理不可变）。

### 2.5 冲突裁决顺位

1. **公理最高**：philosophy.md（卷一）公理系统。
2. **钻石次之**：钻石约束（生理 / 认知不可变边界）对 phyt-DNA 同样生效（§2.3.2）。
3. **管辖冲突裁决**：涉及"文档如何演进" → phyt-DNA；涉及"设计值是什么" → 水之波光。**设计值的裁决权归水之波光，phyt-DNA 管体系的生长，不预判具体值。**
4. **ALIGN 行统一语义**：`@ v<版本>` 一律指体系版本真相源（spec/code 版本），不再混用方法论版本。

---

## 3. 后果 (Consequences)

### 3.1 正面后果

1. ADR-0001 §2.3 越界案例有了正式裁决依据（→ §2.4）。
2. 未来新卷 / 新约束类别必须过本边界检查：SPEC 无视觉值、钻石对 phyt-DNA 生效、archive 纪律统一。
3. 品牌分层有了方法论依据：README 的视觉表述必须显式标 [GENE] 皮肤，不得冒充方法论（见品牌修订）。

### 3.2 负面后果与成本

1. 文档需标注管辖层（system-summary 补充映射表，行动 #1）。
2. 已存在的"方法 / 皮肤混排"表述（README 设计哲学段、navigation.md 三层结构）需按本边界拆开（行动 #2 + ADR-0002 行动 #2）。
