## 1. 上下文 (Context)

### 1.1 问题：校验器从不读硬度列

v10.2.0 交付的校验器（`lumtract-verify.mjs`）读取 §2.4.11 来源类型映射表的三列（ID / 来源类型 / 硬度），但三组检查（已登记、来源类型非空、派生锚存在、平台登记）只消费「来源类型」列——**「硬度」列从未被读取**。判定规则为"含 [ENG]/[派生自]/[新原语]/[平台行为] 任一即通过"，硬度栏写什么都过。

后果：

1. ADR-0002 §2.1.2 的双标注裁决只完成了"硬度栏"一半。N-020~022 的来源类型列只有 `[ENG]`（WCAG 条款），硬度列却声称钻石（生理基础）——属于"半句无锚"的隐蔽冒充：硬度与来源类型不一致，且机器放行。
2. N-010/N-014 的 C-001/C-003 补锚写进了约束正文，未写入映射表——校验器读表不读正文，锚定对机器不可见，等于白写。

### 1.2 版本纪律

本批修订包含约束语义变更（N-020/N-022 硬度降级、N-021 锚定方式变更），按 semver 属 minor，版本号 **v10.2.0 → v10.3.0**（延续 ADR-0002 §1.2 的判定口径）。v10.2.0 保留为历史，不作废。

## 2. 决策 (Decision)

### 2.1 决策内容

**1. 硬度-来源一致性规则（机器可校验，新增）。** 约束硬度含「钻石」→ 来源类型必须含 `[派生自]` 或 `[新原语]`，否则校验器判冒充（阻断）。纯陶土（`[ENG]`）不适用。该规则写入校验器（新增「钻石锚定一致」断言组），使"硬度栏冒充"不依赖人工审查。

**2. N-020 / N-022 降为纯 [ENG] 陶土（修订 ADR-0002 §2.1.2）。** "重复遍历负担"（N-020）与"能力差异需多路径"（N-022）是合规目的，不是生理事实；体系内无既有生理约束锚定它们。WCAG 条款是合规契约（[ENG]），硬度不再声明钻石。

**3. N-021 保留双标注，补 [派生自 P-021]（修订 ADR-0002 §2.1.2 的锚定方式）。** 焦点可见性与有序性是"识别优于回忆"（P-021）的直接应用——键盘用户依赖可见且有序的焦点定位当前位置，隐藏或混乱的焦点迫使用户回忆而非识别。P-021 是体系内既有生理锚，非合规冒充。

**4. N-010 / N-014 补锚进映射表（完成 ADR-0002 "依据待补 C-001 / C-003" 的执行）。** 正文已锚定（上下文切换成本依 C-001 / 出口焦虑依 C-003），映射表来源类型列补齐 `[派生自 C-001]` / `[派生自 C-003]`，使锚定对机器可见。

**5. N-015 同病项补 [派生自 P-011]。** 钻石部分（运动误差 + 探索行为）依赖 P-011；映射表原仅列弱新原语（Stiegler & Karp 假说，证据有限），补 `[派生自 P-011]` 使钻石锚定真实。此为审查未列出的同病项，一并修正。

**6. §2.6 平台行为快照扩展。** 新增四条（均带版本锚点、年度复审）：
- 微信 / 支付宝小程序页面栈上限 **10 层**（navigateTo 超出即失败 `page limit exceeded`）——中文生态独有的平台硬行为，Material 与 HIG 均无；
- Android 系统返回 / 预测性返回（`OnBackInvokedCallback`，Android 13 (API 33) 引入、Android 14+ 默认启用）；
- Android App Links 深链（`autoVerify`，Android 6.0 (API 23)+）；
- Web 浏览器历史栈（History API / `popstate`，前进后退按钮，现行 WHATWG HTML 标准）。

**7. 授权范围明示。** 本 ADR 与 ADR-0002 §5 行动表共同构成对以下改动的完整授权：① N-系列硬度与来源类型修订（含降级 / 补锚 / 双标注）；② §2.4 拆分至 constraints-navigation.md（ADR-0002 行动 #6，已执行）；③ §2.6 平台行为快照的建立与扩展；④ 校验器断言边界扩展（推导完整性 + 硬度-来源一致性）。卷二其余系列（P/C/L/R/D）不在修订范围。ADR-0002 未整体废止——其全部未修订条款继续有效。

### 2.3 不做什么 (Non-Goals)

- **不摘除 N-008 / N-023 的派生锚。** 审查建议"可摘"。核验结论：N-008 的 P-021（可发现性 = 识别优于回忆，与 N-009 同锚）与 N-023 的 P-010/P-011（拖拽对运动障碍用户困难 + 替代按钮 ≥44px）是真实生理锚，摘除只会让派生链变松，无收益。不采纳。
- 不修改 philosophy.md 与 P/C/L/R/D 系列。
- 不把 WCAG 条款整体升为钻石（合规契约 ≠ 生理边界，延续 ADR-0002 纪律）。

## 3. 后果 (Consequences)

### 3.1 正面后果

1. 硬度-来源一致性成为机器可校验规则——"硬度栏冒充"被拦截，不依赖人工审查。
2. 钻石声明收敛：N-020/N-022 不再声称钻石，剩余钻石均有真实锚（派生自既有约束或新原语）。
3. §2.6 覆盖中文生态平台硬行为（小程序 10 层），可机器校验，且是 Material / HIG 盲区。

### 3.2 负面后果与成本

1. N-020/N-022 降级后，无障碍维度在约束库中的钻石声明仅剩 N-021（P-021）与 N-023（P-010/P-011）——不削弱合规效力（校验器仍断言条款存在、必然要求不变），只修正硬度声明。
2. ADR 链变长（ADR-0001 → 0002 → 0003）——符合"已接受 ADR 不可覆盖，只能 Superseded"纪律。
3. 校验器检查项增加（硬度一致性组），输出变长。

### 3.3 风险

| 风险 | 缓解措施 |
| --- | --- |
| 新规则误伤后续新增钻石约束 | 表结构已支持 [派生自]/[新原语] 列；新增钻石约束必须自带来源 |
| 降级后团队误以为无障碍要求消失 | navigation.md §六与校验器仍断言；降级只改硬度声明，不改必然要求 |
| 小程序 10 层等平台行为年度变动 | §2.6 带版本锚点 + 年度复审 |
