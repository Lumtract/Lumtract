## 1. 上下文 (Context)

### 1.1 现状

水之波光（Lumtact）设计哲学体系当前包含四卷：



| 卷  | 文档             | 覆盖范围                                                                                  |
| -- | -------------- | ------------------------------------------------------------------------------------- |
| 卷一 | philosophy.md  | 公理系统（5 条公理、三大实体、推导纪律）                                                                 |
| 卷二 | constraints.md | 约束库：渲染 (R-001\~006)、显示 (D-001\~006)、感知 (P-001\~022)、认知 (C-001\~004)、内容逻辑 (L-001\~003) |
| 卷三 | derivation.md  | 推导引擎：目的验证、约束激活、冲突裁决、降级协议、十一审                                                          |
| 卷四 | archive.md     | 实例档案                                                                                  |

现有约束库的碳基约束（P + C）覆盖了感知与认知的**瞬时界面**维度 —— 亮度阈值、时间感知、运动控制、格式塔、视觉注意力、记忆边界、预测加工。内容逻辑约束（L）覆盖了层级 - 视觉同构、语义色相、状态互斥。

### 1.2 问题

**约束库在 "导航与信息架构" 维度存在结构性缺失。**



* 当前没有任何约束直接规范：导航层级深度与宽度、位置感 (wayfinding)、回溯路径、导航形态选择（栈 / 标签页 / 抽屉 / 搜索）、状态恢复与深链、零态 / 错误态 / 加载态的出路、破坏性操作撤销路径、入口一致性、无障碍导航。

* 仅有 P-020（工作记忆～4 组块）、P-021（识别优于回忆）、P-022（空间记忆依赖网格对齐）三条约束**间接**支撑导航设计，但它们是通用认知约束，未被推导为导航场景的具体硬边界。

* `engineering-guide/logic/state-management.md` 仅覆盖组件级状态互斥（focus > active > hover > default），未触及导航级流转逻辑。

* `navigation.md` 是项目文档的**导航枢纽**（链接四卷体系与组件资产），不是导航设计约束文档。

项目所有者原话："水之波光几乎只在表皮，不在导航和逻辑上。"

### 1.3 方法论要求

phyt-DNA v1.0 方法论的相关铁律：



* **决策拦截**：架构 / 接口变更必须先建 ADR。本决策新增约束类别，属于约束库架构变更。

* **不可修宪**：DNA（philosophy.md 公理）人类才有权改。本决策不修改公理。

* **反腐化**：版本真相源 = spec/code。新增约束必须同步更新约束库版本号。

* **杀掉魔法数字**：禁止硬编码阈值，一切走配置。任何量化阈值必须可追溯到具体文献 / 官方指南，或明确标注 \[ENG] 陶土。

* **反冒充纪律**：陶土冒充钻石是约束库最严重欺诈。新约束的硬度判定必须诚实。

## 2. 决策 (Decision)

### 2.1 决策内容

在约束库（constraints.md）中新增 **§2.4 导航与流转约束**，采用 **N - 系列**约束 ID（N-001 起），覆盖以下九个维度：



| # | 维度         | 核心问题                     | 锚定的已有约束      |
| - | ---------- | ------------------------ | ------------ |
| 1 | 导航层级与广度    | 信息架构的深度 / 宽度如何影响认知负载？    | P-020, P-021 |
| 2 | 位置感与寻路     | 用户如何知道 "我在哪"？迷失的认知代价是什么？ | P-022, C-001 |
| 3 | 回溯与路径记忆    | 返回、面包屑、历史记录的认知基础         | P-021, P-020 |
| 4 | 导航形态选择     | 栈 / 标签页 / 抽屉 / 搜索各自的适用边界 | L-001, P-020 |
| 5 | 状态恢复与深链    | 中断后恢复、外部入口的逻辑要求          | C-001, P-018 |
| 6 | 出路设计       | 零态 / 错误态 / 加载态必须提供出路     | P-014, C-003 |
| 7 | 破坏性操作与撤销   | 不可逆操作的认知安全边界             | P-011, 公理二   |
| 8 | 入口一致性与可预测性 | 同一功能在不同入口的行为一致性          | C-001, L-003 |
| 9 | 无障碍导航      | WCAG 导航条款的硬边界            | P-010, P-019 |

### 2.2 约束格式

新约束严格遵循 constraints.md 既有表格格式：



| 约束 ID | 约束陈述 | 硬度 | 边界声明 | 对设计的必然要求 |
| ----- | ---- | -- | ---- | -------- |

每条约束必须附来源标注 `[PHYS]/[ENG]/[GENE]/[PURPOSE]`，并在约束陈述或边界声明中给出可追溯的文献 / 官方指南出处。

### 2.3 硬度判定纪律



* **钻石**：仅当约束陈述的是碳基生理 / 认知的不可变边界（如工作记忆容量、识别 - 回忆不对称），且有充分学术共识支撑。

* **钢铁**：仅当约束陈述的是硅基物理 / 平台机制的不可变边界（如平台导航栈的行为）。

* **陶土**：工程约定、行业惯例、项目基因。必须明确标注 `[ENG]` 并说明理由。**禁止将行业惯例包装成生理必然。**

* 任何量化阈值：若来自学术文献 / 官方指南，标注出处；若为工程保守约定，标注 `[ENG]` 并说明推导逻辑。

### 2.4 不做什么 (Non-Goals)



* **不修改 philosophy.md**（公理不可变）。

* **不修改已有约束的陈述**（R/D/P/C/L 系列保持原样）。

* **不输出具体设计值**（约束库只输出硬边界，具体值在 archive.md 实例档案中推导）。

* **不覆盖视觉 / 动效细节**（已有 P/R/D 约束覆盖）。

* **不制定特定平台的 UI 规范**（约束是平台无关的硬边界，平台实现在 engineering-guide 中推导）。

## 3. 后果 (Consequences)

### 3.1 正面后果



1. **约束链完整性提升**：从 "瞬时界面感知" 扩展到 "跨界面流转认知"，覆盖用户完整交互旅程。

2. **推导引擎可激活更多约束**：derivation.md 的约束激活流程将包含 N - 系列，冲突裁决引擎可在导航场景中引用 N - 系列约束。

3. **审计清单可扩展**：十一审中的 "层级审" 和 "约束链审" 可引用 N - 系列约束进行导航审计。

4. **engineering-guide 可推导**：新增的 `engineering-guide/navigation/` 目录可基于 N - 系列约束推导具体实现规范。

5. **校验工具可扩展**：`lumtact-verify.mjs` 可增加导航相关校验项。

### 3.2 负面后果与成本



1. **约束库体积增大**：新增约 15-25 条约束，constraints.md 行数增加。需监控单文件 >400 行的解耦阈值（当前 145 行，有充足空间）。

2. **实例档案需复审**：按 system-summary.md 的版本绑定规则，约束库新增约束后，所有依赖的实例档案需复审是否违反新约束。

3. **认知负担增加**：设计者需要学习新的约束类别。通过 navigation.md 的快速索引缓解。

4. **\[PURPOSE] 标注压力**：导航约束高度依赖目的权重分配，实例档案中需更详细地记录导航相关的目的权重。

### 3.3 风险



| 风险                        | 缓解措施                                             |
| ------------------------- | ------------------------------------------------ |
| 新约束含凭空量化阈值，违反 "杀掉魔法数字" 铁律 | 每条约束的数字必须附文献 / 官方指南出处，或标注 \[ENG] 陶土。ADR 审查时逐条核验。 |
| 陶土冒充钻石，违反反冒充纪律            | 硬度判定需在约束陈述中明确说明判定依据。钻石约束必须有学术共识支撑。               |
| 与已有约束重叠或矛盾                | 每条新约束必须锚定已有约束（标注 "由已有约束推出" 或 "扩展边界"），扩展处必须给依据。   |
| 约束过于抽象，无法指导设计             | 每条约束的 "对设计的必然要求" 必须具体到可执行的设计动作。                  |
